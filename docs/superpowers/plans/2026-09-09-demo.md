# Crystal Light implementation plan

Goal: complete connected local demo for the hotel sales meeting.
Architecture: React/Vite pages share a persisted demo store. Public room detail and hall calendars share availability calculations with booking and admin. No backend or external messaging.
Tech stack: React, TypeScript, GSAP, CSS, Lucide, React Router.

- [ ] Create src/data.ts and src/availability.mjs: seeded rooms, bookings, date overlap helpers; test checkout boundaries and room-specific conflicts with node tests.
- [ ] Create src/store.tsx: localStorage persistence for reservations, event inquiries, housekeeping and demo notifications.
- [ ] Create src/components.tsx and src/Calendar.tsx: navigation, modal, demo dock, monthly room/hall availability and date range selection.
- [ ] Create src/Landing.tsx: original hero video, cinematic intro, editorial rooms, hall inquiry/calendar, amenities, gallery, vouchers, FAQ, contact.
- [ ] Create src/Room.tsx and src/Booking.tsx: detail gallery, equipment, unique room calendar, validated booking with extras, promotion and confirmation.
- [ ] Create src/Guest.tsx and src/Admin.tsx: persistent guest changes and cancellation; operational calendar, reservations, guests, events, housekeeping, reports and simulated channels/settings.
- [ ] Create src/styles.css with locked approved palette, typography, responsive breakpoints and reduced motion.
- [ ] Run npm run build, node date tests, desktop/mobile browser flows, inspect screenshots and fix defects.
- [ ] Write README and verification record, commit and push to authorized GitHub origin.

Approved direction: docs/landing-concept.png. Use supplied original hotel media in implementation instead of generated venue. Room-specific detail calendars explicitly requested and approved. All unverified prices/capacities remain demo data. No added wellness claim.
